# Onboarding a New App Pack

This document explains how to add a new application to the Agentic QA Platform.
The Core framework is app-agnostic — everything app-specific lives in the App Pack.

## What is an App Pack?

An App Pack is a self-contained directory with:
- `index.js` — the App Pack config (copy `new-app.pack.js` and fill in placeholders)
- `pages/` — Page Objects specific to this app (generated by Explorer, refined by humans)
- `tests/` — test specs (generated by Generator, reviewed by humans)
- `data/` — static test fixtures if needed

## Steps to onboard a new app

### 1. Create the App Pack directory

mkdir -p packs/<your-app>/{pages,tests/smoke-tests,tests/regression,data}
cp templates/app-pack/new-app.pack.js packs/<your-app>/index.js


### 2. Fill in the placeholders
Open `packs/<your-app>/index.js` and replace all `{{PLACEHOLDER}}` values:
- `APP_NAME` — kebab-case identifier e.g. `my-app`
- `APP_DESCRIPTION` — one sentence about what the app does
- `APP_BASE_URL` — the dev/staging URL
- `PROJECT_KEY` — your Jira/Linear project key
- `TEAM_OR_PERSON` — who owns this App Pack

### 3. Run the Explorer agent
The Explorer navigates the app and proposes initial Page Objects

ACTIVE_APP_PACK=packs/<your-app> npx playwright test --grep "explorer"

Review the Explorer's PR and merge the Page Objects you want to keep.

### 4. Configure the Work Management Connector
Add to your `.env.local`:

WORK_MANAGEMENT_PROVIDER=jira
JIRA_BASE_URL=https://your-org.atlassian.net
JIRA_EMAIL=your-email@example.com
JIRA_API_TOKEN=your-api-token
JIRA_PROJECT_KEY=YOUR_PROJECT


### 5. Start generating specs
Once tickets are in "Ready for QA" status, the Generator will automatically
create spec files and open PRs. Review and merge to activate them in CI.

### 6. Promote autonomy levels
Start with all agents at L2. After reviewing the audit log (`heal-audit.log.jsonl`,
`analyst-diagnosis.jsonl`) and confirming reliability, promote to L3 in `index.js`.

## Autonomy promotion checklist

Before promoting an agent from L2 → L3:
- [ ] Review last 10 audit log entries for this agent
- [ ] Confirm < 10% of decisions were reversed or required manual correction
- [ ] Update `autonomyPolicy` in `packs/<your-app>/index.js`
- [ ] Commit and open a PR for the autonomy change (treat it like a config change)

## What NOT to put in an App Pack
- Business logic unrelated to testing
- Credentials or secrets (use .env.local + GitHub Secrets)
- Generated files (test-results/, allure-report/, visual/diffs/)
- Copies of Core framework files (BasePage, HealingEngine, etc.)
